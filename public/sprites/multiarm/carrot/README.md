# Carrot multi-arm runtime data, SIDE VIEW (for the coding agent)

**Same format as `figures/player-potato/multiarm/`** (the front-facing v2 spud) **plus the side-view fields, named exactly like
the chili's side export** (`figures/player-chili/multiarm/`): `sockets.json` `"view": "side"`, every slot `side: +1` with a
`"layer"` (`front`/`back`) and natives naming their hero arm (`"hero": "R"` near / `"L"` far), a `"mirror"` note,
`bud: null`; plus two carrot extras: `arms.emptyHand: null` and `weapons.json` `alt.imgsBack`. `compose_ref.py` = the chili's
side compose_ref (sheet id changed) + those two switches, all data-driven (a front-facing export still renders exactly as
before) - port them to `multiarm.ts` (see "Side view" at the bottom). `multiarm.ts` also needs `ROOT` / `SHEET_ID` per hero
(`player-carrot-armless`); it is hard-wired to the potato today. The front-facing carrot export is kept in
`../frontal_v2/multiarm/`.

The carrot gets one extra arm per weapon, up to 6 arms. Arms, hands, weapons and fx are composed **at runtime** from
painted parts. Pre-baking every combination would need about 12,000 cells. Everything in this folder is generated by
`export.py` from the painted parts sheets. `compose_ref.py` is the executable spec: it reads only these files and
renders `../previews/multiarm_side_showcase.mp4`. Port `MultiArm.arm_layers()` and `MultiArm.frame()` to TypeScript 1:1.

## Files

| file | what |
|---|---|
| `player-carrot-armless.{json,webp,png}` | Body + legs only. Same schema, clip names, timings, events, `anchor`, `feetY` and `gameRadius` as `public/sprites/player-carrot.json`. Play it with the normal sheet player in multi-arm mode, instead of the hero sheet. Its cell indices differ (cells deduped separately), so always go through clip frame order. |
| `body_track.json` | `clips[clip][frameIndex]` follows the same frame order as the armless sheet's clips. `m` is a 2×3 matrix: **body px → hero cell px**. `arms:false` means don't draw arms (painted death burst frames). `tint` is `[r,g,b,amount]`: apply the same flash to the arms. `native.R` / `native.L` are the hero's own NEAR (front layer) / FAR (back layer) native-arm keys for that frame. `secondary[clip][frame][slotIndex]` gives `{raise, elbow, wrist}` sway for every slot. |
| `parts.png` + `parts.json` | Every arm, hand, weapon and fx painting, **pre-scaled so 1 part px = 1 body px**. `rect` = atlas rect. `points` = named pivots in part px. `dir0`/`fore0`/`axis` = painted directions in degrees. |
| `sockets.json` | Slot geometry (body px) and `layouts["1".."6"]`, i.e. the slot list plus per-count overrides (the layout changes with arm count). `arms` gives the art per slot type, `sproutScale` and `behindBodyZ`. |
| `weapons.json` | Per weapon: `img`, `family`, `wood`, `restAim`, `shotOffset`, hand per front/back slot, `alt` painting (slingshot drawn), and the release `fx` placement rule. |
| `families.json` | Attack pose clips per family (`melee-swing`, `melee-stab`, `ranged-recoil`), the `sprout` pop, `aimClamp` (±50°), `jitterMs` [80,200], `sproutScale` 0.8, `armTurnShare` 0.6, `handD`, and the loadout rule. |

## Conventions

- **Units**: body px are px of the side carrot's upright body canvas (K = 0.62 rest px per body px; the shared spud weapons
  were rescaled so they keep their on-screen size). Angles are screen degrees with y down: 0 = facing direction (right),
  -90 = up, + = clockwise.
- **Side view**: every slot is canonical RIGHT-facing; `side` only tells the layer (+1 front, -1 back). No per-slot
  mirroring. When the target is behind the hero (or it walks left), compose as facing right with the target mirrored
  (`x' = 2*anchor.x - x`) and draw the whole composite mirrored about the anchor (the flip the game already does for sheets).
- `T` = translate, `R(d)` = rotate by d degrees clockwise (y-down matrix `[[c,-s],[s,c]]`), `S(k)` = uniform scale.
- **Draw order**: sort by z. The body cell (armless sheet frame) is at **z = 10**. Slots with `z < 10` draw behind the body
  using the painted dark arm and hands. Slots with `z > 10` draw in front (light painted arm and hands).
- **Final transform per part**: `world = cellToScreen · body_track.m · (Wf ·) X_part`. Here `cellToScreen` is what the
  sheet player already does for the cell: anchor, `fit`, frame `ox/oy`, `scaleX/Y`, facing.

## Per arm (`compose_ref.MultiArm.arm_layers`)

```
pose  = secondary[clip][frame][slot.index]            (natives: the hero's native keys for that frame)
if attacking: key = family key at t_attack (t = time since this arm's attack start - jitter); pose = key,
              pose.raise += 0.3 * secondary.raise
aim_c = key.aim  or  weapon.restAim + pose.wrist                       (canonical)
dc    = target ? clamp(wrap(angle(slot world -> target) - refWorld), ±aimClamp) (sign-flipped for side -1, front-facing view only) : 0
        refWorld = (key.aim or restAim) + shotOffset, mirrored (180 - x) on side -1
aim_c += dc ;  k = native ? 1 : sproutScale * grow
BENT (native, unless key.straight):    parts <art>_upper / <art>_fore  (art = sockets.arms.native[slot]: arm_L for midN, arm_dark_bent for midF)
   d_up  = slot.dir - raise + armTurnShare*dc
   U     = T(P) R(d_up - dir0) S(k) T(-shoulder)
   F     = U T(elbow) R(-pose.elbow) T(-elbow)      (+ thrust*k along d_fore, pre-multiplied)
   d_fore= d_up + (fore0 - dir0) - pose.elbow ;  wrist = F(wrist)     z: fore z, upper z+0.02
STRAIGHT (sprouted always, natives when key.straight):  sockets.arms.sprouted front / back (straight / straight_dark)
   d_fore= key.straight ? aim_c : slot.dir - raise + armTurnShare*dc
   L     = T(P) R(d_fore - dir0) S(k) T(-shoulder) (+ thrust) ;  wrist = L(wrist)
HAND  fist34 (club/knife, front): H = T(wrist) R(aim_c) S(k) T(-fist34.wrist); grip = H(fist34.grip)
      camera-facing fist / fist_dark / palm / palm_dark: grip = wrist + handD*k along d_fore;
      H = T(grip) R(d_fore - 22 [+ wrist for palms]) S(k) T(-part.grip)
WEAPON  Wm = T(grip) R(aim_c - weapon.axis) S(k) T(-weapon.grip)   z+0.03, under the hand (z+0.06)
      alt (slingshot drawn, key.alt): img = (front ? alt.imgs : alt.imgsBack ?? alt.imgs)[slot.index % len], same formula with its grip/axis,
      z+0.06, and do NOT draw the hand (it is painted into the alt)
BUD   front slots only, when sockets.bud is set (null on the side carrot): T(P) S(k) T(-bud.center)  z+0.04
FX on the key whose show contains "release":
      swingArc (club smear): head = Wm(club.head); a = angle(P->head); mid = a - back;
                             C = P + radius*|head-P|*(cos mid, sin mid); M = T(C) R(mid) S(k) T(-bulge); z 9.5 (behind body)
      alongAim (knife streak) / alongShot (sling puff): at = Wm(weapon.points[at]); d = aim_c (+shotOffset for alongShot);
                             pos = at + ahead*k*dir(d) + side*k*normal(d); M = T(pos) R(d) S(k) T(-anchor); z 14
```

## Rules the game should apply

- **Layout**: `layout(n)` = `layouts[str(clamp(n,1,6))]`. Natives (`midN` near, `midF` far on the side carrot) are always present. Slot index =
  arm number - 1.
- **Weapon to slot assignment**: brute-force the permutations (at most 720). Cost = 10 per extra wooden weapon on a side, +3 per
  vertically adjacent wooden pair, +1 per weapon that changes slot vs the previous assignment. That keeps the
  arms stable when a new arm sprouts. "No two wooden weapons on one side" is impossible for 3 wooden weapons on 2 sides,
  so it is minimised, not enforced.
- **Desync**: each arm starts its attack after an extra uniform 80–200 ms, re-rolled every cycle (seeded by slot index and
  cycle).
- **Sprout**: play `sprout` keys on the new arm. `scale` multiplies k. `bud` swells the painted bud at the slot when the hero has one (z 10.5,
  scale×0.8; the side carrot has none). Show `fx_dust` at the slot on the first 3 keys. Optional: body squash (the body sheet is baked, so skip it or apply it as
  frame scaleX/Y).
- Fire the weapon's projectile/hit on the family key that has `ev: ["release"]`.

## Known limits

- Arms behind the body draw behind the legs too (the legs are inside the body cell).
- With 6 weapons the front of the carrot gets crowded (5-6 weapons all point forward from the belly); 1-4 read well.
- No painted dark palm: `palm_dark` is the light palm with a palette tint (`emptyHand` is null, so the runtime never draws
  palms anyway; the hero uses it on the release fling).

## Side view (what changed vs the front-facing format / compose_ref)

- `compose_ref.py` switches (chili's, marked `SIDE:`): slots carry `layer` instead of left/right sides (all `side` +1, so
  no per-slot mirroring and the aim reference is the right side's), wood-per-side cost counted per layer, native slots
  replay `track.native[slot.hero]`, no bud, `frame(..., facing=-1)` = target mirrored about `anchor.x`, compose, mirror the
  canvas about `anchor.x`. Carrot extras: `arms.emptyHand == null` -> weapon-less arms draw no palm (the painted arm ends in
  its own small fist); `alt.imgsBack` on back-layer slots (dark fist + dark-tinted pinch hand).
- **Slots (a tidy ladder down the body side)**: natives `midN` (near arm, front layer, painted `arm_L`, holds weapon 1 in
  front of the body) and `midF` (far arm, back layer, painted `arm_dark_bent`; hangs behind, reaches forward under the body
  when it holds a weapon: layouts 2-6 override its `dir`). Sprouts alternate back / front: `upF` (chest, emerges at the
  front edge), `lowN`, `lowF`, `upN` (just under the chin). Sprouted art = painted `straight` (front) / `straight_dark` (back).
- **Hands**: painted `fist` (front) / `fist_dark` (back) for every weapon, placed `handD` = 6 past the wrist along the
  forearm with `R(d_fore - 22)` as before (covers the arm's own small painted fist).
- **Weapons**: `slingshot` (carrot side painting, `restAim` -62 = the hero's, alt `sling_drawn` / `sling_drawn_dark` =
  the painted drawn slingshot with the carrot's painted pinch hand on the pebble + the fist baked on the grip), `spear`
  (carrot frontal painting), shared `club`, `knife`, `fx_*` (from the spud via `../frontal_v2/multiarm`, rescaled x1.32).
- **Native rest aim -62** (team convention): `nativeAimShift` 0. The `attack` clip carries no `native` keys (attacking arms
  take the family keys; replaying the hero's own attack would add its raise twice).
- `families.json` = the spud's motion templates; `handD` 6, `handRot` 22.
- Hero-only (not runtime): the two-arm draw (far arm IK onto the painted pinch hand of the long-band drawn slingshot).
