# Spud multi-arm runtime data, SIDE VIEW (for the coding agent)

2026-10-17: the spud is now three-quarter, facing right (like the legacy spud). Same file format as the front-facing
export (kept in `../frontal_v2/multiarm/`), plus `"view":"side"`, a per-slot `layer` and a `mirror` note in
`sockets.json`, and one optional family-key flag (`weaponBehind`). `compose_ref.py` still renders the frontal exports
unchanged. **Side-view differences in one line:** every slot is `side: 1` (no per-slot mirroring), slots ending in `R` are
the near side (layer front, drawn over the body), `L` the far side (layer back, dark arm behind the body), and the game
mirrors the whole composite when the hero faces left.

The spud gets one extra arm per weapon, up to 6 arms. Arms, hands, weapons and fx are composed **at runtime** from
painted parts. Pre-baking every combination would need about 12,000 cells. Everything in this folder is generated by
`export.py` from the painted parts sheets. `compose_ref.py` is the executable spec: it reads only these files and
renders `../previews/multiarm_showcase.mp4`. Port `MultiArm.arm_layers()` and `MultiArm.frame()` to TypeScript 1:1.

## Files

| file | what |
|---|---|
| `player-potato-armless.{json,webp,png}` | Body + legs only. Same schema, clip names, timings, events, `anchor`, `feetY` and `gameRadius` as `public/sprites/player-potato.json`. Play it with the normal sheet player in multi-arm mode, instead of the hero sheet. Its cell indices differ (24 cells after dedupe), so always go through clip frame order. |
| `body_track.json` | `clips[clip][frameIndex]` follows the same frame order as the armless sheet's clips. `m` is a 2×3 matrix: **body px → hero cell px**. `arms:false` means don't draw arms (painted death burst frames). `tint` is `[r,g,b,amount]`: apply the same flash to the arms. `native.R/L` are the hero's own native-arm keys for that frame. `secondary[clip][frame][slotIndex]` gives `{raise, elbow, wrist}` sway for every slot. |
| `parts.png` + `parts.json` | Every arm, hand, weapon and fx painting, **pre-scaled so 1 part px = 1 body px**. `rect` = atlas rect. `points` = named pivots in part px. `dir0`/`fore0`/`axis` = painted directions in degrees. |
| `sockets.json` | Slot geometry (body px) and `layouts["1".."6"]`, i.e. the slot list plus per-count overrides (the layout changes with arm count). `arms` gives the art per slot type, `sproutScale` and `behindBodyZ`. |
| `weapons.json` | Per weapon: `img`, `family`, `wood`, `restAim`, `shotOffset`, hand per front/back slot, `alt` painting (slingshot drawn), and the release `fx` placement rule. |
| `families.json` | Attack pose clips per family (`melee-swing`, `melee-stab`, `ranged-recoil`), the `sprout` pop, `aimClamp` (±50°), `jitterMs` [80,200], `sproutScale` 0.8, `armTurnShare` 0.6, `handD`, and the loadout rule. |

## Conventions

- **Units**: body px are the side spud's `parts/cc/body.png` px (176 x 214). Angles are screen degrees with y down: 0 = facing direction
  (right), -90 = up, + = clockwise.
- **Side view: every slot has `side: 1`**, so the per-slot mirror (`Wf`, used by the frontal export for `side:-1`) never
  applies. When the hero faces left (walking left, or its target is behind it) the game flips the **whole composite**
  (body cell + every arm layer) about the anchor x, exactly as it already does for sheets. Do the aim maths in the
  unflipped frame: mirror the target's x about the anchor first (`compose_ref.MultiArm.frame(facing=-1)` does both;
  `facing_for()` is the flip rule with a 4 px dead zone).
- `layer`: `front` slots (z > 10) are the near side: light arm, light hands, bud on the shoulder. `back` slots (z < 10)
  are the far side: dark arm + dark fist, behind the body. Shoulders are stacked down each side: near `upR`/`midR`/`lowR`
  down the front edge, far `upL` (crown, reaching up over the head) / `midL` (back) / `lowL` (low back, reaching back).
  Layout order alternates near/far: 3 = +upR, 4 = +upL, 5 = +lowR, 6 = +lowL.
- `T` = translate, `R(d)` = rotate by d degrees clockwise (y-down matrix `[[c,-s],[s,c]]`), `S(k)` = uniform scale.
- **Draw order**: sort by z. The body cell (armless sheet frame) is at **z = 10**. Slots with `z < 10` draw behind the body
  using the painted dark arm and hands. Slots with `z > 10` draw in front, with the shoulder bud capping the joint.
- **Final transform per part**: `world = cellToScreen · body_track.m · (Wf ·) X_part`. Here `cellToScreen` is what the
  sheet player already does for the cell: anchor, `fit`, frame `ox/oy`, `scaleX/Y`, facing.

## Per arm (`compose_ref.MultiArm.arm_layers`)

```

if attacking: key = family key at t_attack (t = time since this arm's attack start - jitter); pose = key,
              pose.raise += 0.3 * secondary.raise
aim_c = key.aim  or  weapon.restAim + pose.wrist                       (canonical)
dc    = target ? clamp(wrap(angle(slot world -> target) - refWorld), ±aimClamp) (sign-flipped for side -1) : 0
        refWorld = (key.aim or restAim) + shotOffset, mirrored (180 - x) on side -1
aim_c += dc ;  k = native ? 1 : sproutScale * grow
BENT (native, unless key.straight):    parts <art>_upper / <art>_fore  (art = arm_bent2 for midR, arm_dark_bent2 for midL)
   d_up  = slot.dir - raise + armTurnShare*dc
   U     = T(P) R(d_up - dir0) S(k) T(-shoulder)
   F     = U T(elbow) R(-pose.elbow) T(-elbow)      (+ thrust*k along d_fore, pre-multiplied)
   d_fore= d_up + (fore0 - dir0) - pose.elbow ;  wrist = F(wrist)     z: fore z, upper z+0.02
STRAIGHT (sprouted always, natives when key.straight):  long_cut (front) / long_dark_cut (back)
   d_fore= key.straight ? aim_c : slot.dir - raise + armTurnShare*dc
   L     = T(P) R(d_fore - dir0) S(k) T(-shoulder) (+ thrust) ;  wrist = L(wrist)
HAND  fist34 (club/knife, front): H = T(wrist) R(aim_c) S(k) T(-fist34.wrist); grip = H(fist34.grip)
      camera-facing fist / fist_dark / palm / palm_dark: grip = wrist + handD*k along d_fore;
      H = T(grip) R(d_fore - 22 [+ wrist for palms]) S(k) T(-part.grip)
WEAPON  Wm = T(grip) R(aim_c - weapon.axis) S(k) T(-weapon.grip)   z+0.03, under the hand (z+0.06)
      key.weaponBehind and front slot: weapon z = behindBodyZ - 0.6 (club cocked over the shoulder, behind the head)
      alt (slingshot drawn, key.alt): img = alt.imgs[slot.index % 2], same formula with its grip/axis,
      z+0.06, and do NOT draw the hand (it is painted into the alt)
BUD   front slots only: T(P) S(k) T(-bud.center)  z+0.04
FX on the key whose show contains "release":
      swingArc (club smear): head = Wm(club.head); a = angle(P->head); mid = a - back;
                             C = P + radius*|head-P|*(cos mid, sin mid); M = T(C) R(mid) S(k) T(-bulge); z 9.5 (behind body)
      alongAim (knife streak) / alongShot (sling puff): at = Wm(weapon.points[at]); d = aim_c (+shotOffset for alongShot);
                             pos = at + ahead*k*dir(d) + side*k*normal(d); M = T(pos) R(d) S(k) T(-anchor); z 14
```

## Rules the game should apply

- **Layout**: `layout(n)` = `layouts[str(clamp(n,1,6))]`. Natives (`midR`, `midL`) are always present. Slot index =
  arm number - 1.
- **Weapon to slot assignment**: brute-force the permutations (at most 720). Cost = 10 per extra wooden weapon on a side, +3 per
  vertically adjacent wooden pair, +1 per weapon that changes slot vs the previous assignment. That keeps the
  arms stable when a new arm sprouts. "No two wooden weapons on one side" is impossible for 3 wooden weapons on 2 sides,
  so it is minimised, not enforced.
- **Desync**: each arm starts its attack after an extra uniform 80–200 ms, re-rolled every cycle (seeded by slot index and
  cycle).
- **Sprout**: play `sprout` keys on the new arm. `scale` multiplies k. `bud` swells the painted bud at the slot (z 10.5,
  scale×0.8). Show `fx_dust` at the slot on the first 3 keys. Optional: body squash (the body sheet is baked, so skip it or apply it as
  frame scaleX/Y).
- Fire the weapon's projectile/hit on the family key that has `ev: ["release"]`.

## Known limits

- Arms behind the body draw behind the legs too (the legs are inside the body cell).
- Only the club is painted on the side sheet. The knife and the relaxed slingshot (and the streak/puff/dust fx) are
  borrowed from the frontal spud sheet (no hand painted into them, so they fit). The drawn slingshot `alt` is dropped:
  its painting carries the frontal spud's yellow hand, which doesn't match the side spud's legacy-toned skin.
- No dark palm is painted: `palm_dark` is the dark fist (empty far arms show a closed fist).
- The native bent arm swaps to the straight painting on the knife stab. It's a 1-frame swap and reads as a snap.
- Near-side extra arms (`upR`) cross the mouth/cheek at rest; at game size it reads as an arm in front of the body.

## Weapons v2 (2026-10-18)
`parts.png` carries the bold v2 weapon paintings, **baked bigger** (`weapons.json` → `bakedScale` is informational).
The game's weapon drawScale (chaos.ts `read.weaponMelee/weaponRanged`) must be **1.0**. `weapons.json` has keys for every game
weapon id, so `paintName()` finds them directly. If `sockets.arms.raised.back` is present, back-layer slots on `raised:true`
keys use that dark painting (see compose_ref). Details: art/WEAPONS_V2.md.
