# Chili multi-arm runtime data, SIDE VIEW (for the coding agent)

**Same format as `figures/player-potato/multiarm/` (the spud), plus the side-view additions of
`art/HERO_SIDE_VIEW_BRIEF.md`** (section "Side view" below: `view`, per-slot `layer` + `hero`, `mirror`, the painted
raised arm, the `aboveArm` fx z). Without those keys the runtime behaves exactly like the spud's. Chili-specific notes
are at the end. The front-facing export this replaced is kept in `../frontal_v2/multiarm/`.

The chili gets one extra arm per weapon, up to 6 arms. Arms, hands, weapons and fx are composed **at runtime** from
painted parts. Pre-baking every combination would need about 12,000 cells. Everything in this folder is generated by
`export.py` from the painted parts sheets. `compose_ref.py` is the executable spec: it reads only these files and
renders `../previews/multiarm_side_showcase.mp4`. Port `MultiArm.arm_layers()` and `MultiArm.frame()` to TypeScript 1:1.

## Files

| file | what |
|---|---|
| `player-chili-armless.{json,webp,png}` | Body + legs only. Same schema, clip names, timings, events, `anchor`, `feetY` and `gameRadius` as `public/sprites/player-chili.json`. Play it with the normal sheet player in multi-arm mode, instead of the hero sheet. Its cell indices may differ from the hero sheet after dedupe, so always go through clip frame order. |
| `body_track.json` | `clips[clip][frameIndex]` follows the same frame order as the armless sheet's clips. `m` is a 2×3 matrix: **body px → hero cell px**. `arms:false` means don't draw arms (painted death burst frames). `tint` is `[r,g,b,amount]`: apply the same flash to the arms. `native.R/L` are the hero's own native-arm keys for that frame. `secondary[clip][frame][slotIndex]` gives `{raise, elbow, wrist}` sway for every slot. |
| `parts.png` + `parts.json` | Every arm, hand, weapon and fx painting, **pre-scaled so 1 part px = 1 body px**. `rect` = atlas rect. `points` = named pivots in part px. `dir0`/`fore0`/`axis` = painted directions in degrees. |
| `sockets.json` | Slot geometry (body px) and `layouts["1".."6"]`, i.e. the slot list plus per-count overrides (the layout changes with arm count). `arms` gives the art per slot type, `sproutScale` and `behindBodyZ`. |
| `weapons.json` | Per weapon: `img`, `family`, `wood`, `restAim`, `shotOffset`, hand per front/back slot, `alt` painting (slingshot drawn), and the release `fx` placement rule. |
| `families.json` | Attack pose clips per family (`melee-swing`, `melee-stab`, `ranged-recoil`), the `sprout` pop, `aimClamp` (±50°), `jitterMs` [80,200], `sproutScale` 0.85, `armTurnShare` 0.6, `handD`, and the loadout rule. |

## Conventions

- **Units**: body px are `parts/legacy/body.png` px (= the legacy chili's rest-crop px + 10; the body IS the legacy painting). Angles are screen degrees with y down: 0 = facing direction
  (right), -90 = up, + = clockwise.
- Slots are **canonical** (described as if on the right). For `side:-1`, mirror the whole arm chain about the slot x:
  `Wf = T(P.x,0)·FlipX·T(-P.x,0)`. Don't mirror the bud. When the hero faces left, the game flips the whole composite as it
  already does for sheets.
- `T` = translate, `R(d)` = rotate by d degrees clockwise (y-down matrix `[[c,-s],[s,c]]`), `S(k)` = uniform scale.
- **Draw order**: sort by z. The body cell (armless sheet frame) is at **z = 10**. Slots with `z < 10` draw behind the body
  using the painted dark arm and hands. Slots with `z > 10` draw in front, with the shoulder bud capping the joint.
- **Final transform per part**: `world = cellToScreen · body_track.m · (Wf ·) X_part`. Here `cellToScreen` is what the
  sheet player already does for the cell: anchor, `fit`, frame `ox/oy`, `scaleX/Y`, facing.

## Per arm (`compose_ref.MultiArm.arm_layers`)

```
pose  = secondary[clip][frame][slot.index]            (natives: the hero's native keys for that frame)
if attacking: key = family key at t_attack (t = time since this arm's attack start - jitter); pose = key,
              pose.raise += 0.3 * secondary.raise
aim_c = key.aim  or  weapon.restAim + pose.wrist                       (canonical)
dc    = target ? clamp(wrap(angle(slot world -> target) - refWorld), ±aimClamp) (sign-flipped for side -1) : 0
        refWorld = (key.aim or restAim) + shotOffset, mirrored (180 - x) on side -1
aim_c += dc ;  k = native ? 1 : sproutScale * grow
BENT (native, unless key.straight):    parts <art>_upper / <art>_fore  (art = arm1 for midN, arm_dark1 for midF)
   d_up  = slot.dir - raise + armTurnShare*dc
   U     = T(P) R(d_up - dir0) S(k) T(-shoulder)
   F     = U T(elbow) R(-pose.elbow) T(-elbow)      (+ thrust*k along d_fore, pre-multiplied)
   d_fore= d_up + (fore0 - dir0) - pose.elbow ;  wrist = F(wrist)     z: fore z, upper z+0.02
STRAIGHT (sprouted always, natives when key.straight):  long_cut (front) / long_dark_cut (back)

   L     = T(P) R(d_fore - dir0) S(k) T(-shoulder) (+ thrust) ;  wrist = L(wrist)
HAND  fist34 (club/knife, front): H = T(wrist) R(aim_c) S(k) T(-fist34.wrist); grip = H(fist34.grip)

      H = T(grip) R(d_fore - 22 [+ wrist for palms]) S(k) T(-part.grip)
WEAPON  Wm = T(grip) R(aim_c - weapon.axis) S(k) T(-weapon.grip)   z+0.03, under the hand (z+0.06)
```

## Rules the game should apply

- **Layout**: `layout(n)` = `layouts[str(clamp(n,1,6))]`. Natives (`midN`, `midF`) are always present. Slot index =
  arm number - 1.
- **Weapon to slot assignment**: brute-force the permutations (at most 720). Cost = 10 per extra wooden weapon on a side, +3 per
  vertically adjacent wooden pair, +1 per weapon that changes slot vs the previous assignment. That keeps the
  arms stable when a new arm sprouts. "No two wooden weapons on one side" is impossible for 3 wooden weapons on 2 sides,
  so it is minimised, not enforced.
- **Desync**: each arm starts its attack after an extra uniform 80–200 ms, re-rolled every cycle (seeded by slot index and
  cycle).
- **Sprout**: play `sprout` keys on the new arm. `scale` multiplies k. `bud` swells the painted bud at the slot (z 10.5,
  scale×0.8). Show `fx_dust` at the slot on the first 3 keys. Optional: body squash (the body sheet is baked, so skip it or apply it as
  frame scaleX/Y).
- Fire the weapon's projectile/hit on the family key that has `ev: ["release"]`.

## Known limits

- Arms behind the body draw behind the legs too (the legs are inside the body cell).
- Back-layer weapons are partly hidden by the body by design (far side); their tips/heads show above or in front of it.
- The native bent arm swaps to the straight painting on a stab key (1-frame swap).
- No painted dark open hand, dark raised arm, or side-view cleaver yet (see ../NOTES.md "still to paint").

## Side view (new keys; compose_ref.py lines marked `SIDE:`)

- `sockets.view = "side"`. The hero faces its walking direction (right in the data). Every slot is canonical
  facing-right (`side: 1`); nothing is mirrored per slot.
- **`layer`** per slot: `front` = near side, z > 10, drawn over the body (red arms `arm1` / `long_cut`, hands `fist34`
  / `fist` / `palm`); `back` = far side, z < 10, behind the body (dark arms `arm_dark1` / `long_dark_cut`, hand
  `fist_dark`). The shoulders form a ladder down each body side, alternating front/back as arms are added:
  `midN`(front, native knife arm) `midF`(back, native empty arm) `upN` `upF` `lowN` `lowF`.
  The loadout rule groups wooden weapons per **layer** instead of per side.
- **`hero`** on the two native slots names the hero arm whose `body_track.native` keys they replay (`R` = near arm,
  `L` = far arm). The attack clip carries no `native` keys: attacking arms take the family keys (otherwise the
  family's `raise += 0.3 * base.raise` would count the hero's raise twice).
- **`mirror`**: when the hero walks left, or the target is behind it (target x < anchor x in facing-right cell px),
  mirror the WHOLE composite (body cell + every arm) about the anchor x, exactly as the game already flips sheets.
  Compose facing right with the target mirrored into facing-right space (`x' = 2*anchor.x*cell - x`), then flip:
  `compose_ref.MultiArm.frame(..., facing=-1)`; `facing_for(target, walking)` picks the facing. Frame `ox` flips sign.
  Arms therefore only aim into the facing half-plane (±aimClamp around the weapon rest aim).
- **Raised arm** (`sockets.arms.raised`): a family key with `raised: true` (the `melee-slash` windup) on a FRONT-layer
  arm swaps the whole arm for the painted `raised` part (one piece, keeps its painted fist):
  `L = T(P) R(rrot + armTurnShare*dc) S(k) T(-raised.shoulder)`; weapon `Wm = T(L(raised.grip)) R(aim_c - axis) S(k) T(-weapon.grip)`
  at z `arms.raised.weaponZ` (9.5 = behind the body, so the blade hangs back **behind the head**); no separate hand.
  The `raised.shoulder` point lies below the painting (a built-in shrug; the arm root is hidden behind the body).
  Back-layer arms ignore `raised` and use the key's `raise`/`elbow` (fallback values are in the key).
- **fx z `aboveArm`** = slot z + 0.5 (over the arm and weapon on front slots, still behind the body on back slots).
  The knife and cleaver slash use it, as on the hero sheet (the arc is drawn over the knife arm).
- `sockets.bud = null`: the side arms have painted round shoulders, no bud is drawn (the sprout skips the bud swell
  and keeps the dust).

## Chili specifics (all data)

- **Weapons**: `knife` (side-sheet painting, family `melee-slash`, painted slash `fx_slash` via `swingArc`, z
  `aboveArm`), `cleaver` (the frontal chili sheet's cleaver painting, `melee-swing`, `fx_slash`), plus the shared spud
  `club` (`melee-swing`, `fx_smear`) and `slingshot` (`ranged-recoil`, `fx_puff`), rescaled to the same screen size
  as on the spud (spud part px × 0.82).
- **`melee-slash`** = the hero's knife slash: windup 60 ms (raised arm, blade back behind the head), strike 45 ms
  (`release`), follow-through 70 ms, settle 80 ms. The follow-through also has `show:["release"]` (arc on two keys).
  The hero sheet shows a smaller trailing piece of the arc on the follow-through; the runtime reuses the strike
  placement rule (difference is cosmetic).
- `fx_slash` is the side sheet's slash, pre-rotated so the runtime rotation at the hero strike shows it as painted:
  `bulge` = the spray LEAD end on the blade path, the thin crescent trails back up over the head.
- Hands: `fist34` = painted fist-on-handle with the painted handle removed (handle along +x). `fist`, `fist_dark`,
  `palm` are pre-rotated so the camera-hand rule `R(d_fore - 22)` shows them upright on a hanging arm.
  `palm_dark` = `fist_dark` (no dark open hand painted: the far empty hand stays a fist, as on the legacy chili).
- Native rest aim is −62° (the runtime maps native `aim` to `wrist = aim + 62`); the hero knife rests at −62 too.
